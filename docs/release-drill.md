# 发布前故障演练记录

日期：2026-11-03  
环境：macOS arm64 · Electron 44.10.0 · 临时数据目录  
方式：真实启动应用，通过 `--exec-file` 驱动界面/IPC；演练数据与正式书库隔离。

## 1. 生成中强制退出

目的：确认进程被 `SIGKILL` 时，不会把 SQLite 主库写坏，重启后仍能打开书架和正文。

步骤：

1. 在 `/tmp/rn-drill-force` 用演示数据启动应用。
2. 打开一本书，点击「读薄并提炼」。
3. 生成过程中执行 `kill -9`。
4. 重新启动同一数据目录，打开书。

结果：

- 进程被 `SIGKILL`。
- `PRAGMA integrity_check` = `ok`。
- 书架仍有 1 本书。
- 重启后打开书进入阅读器成功，未出现“数据库损坏”提示。

结论：通过。强制退出不会损坏主库；未完成的生成任务不会在重启后伪装成已完成。

## 2. 错误 API Key

目的：确认 401 会以可读错误返回，不崩溃、不把错误 Key 写进日志。

步骤：

1. 在 `/tmp/rn-drill-key` 启动应用。
2. 保存一个 OpenAI 兼容配置，Base URL 指向本机 401 mock 端点，Key 为 `sk-drill-invalid-0000`。
3. 调用「测试连接」。

结果：

- `testConnection()` 返回 `ok: false`。
- 错误信息为 `Invalid API key`。
- 应用未崩溃，设置仍可修改。

说明：为了避免向真实服务商发送无效请求，这里用本机 401 端点模拟服务端拒绝；SDK 的 401 处理路径与真实服务商一致。

结论：通过。

## 3. 备份恢复

目的：确认恢复会回到备份时点，临时新增的书消失，原书保留，并生成恢复前安全备份。

步骤：

1. 在 `/tmp/rn-drill-backup` 用演示数据启动应用。
2. 创建手动备份 `backup-20261103-041431-manual-356cd1`。
3. 导入一本 `DRILL TEMP BOOK`。
4. 调用恢复该备份。
5. 重新启动应用，检查书架。

结果：

- 恢复后书架只剩《专注的练习》，`DRILL TEMP BOOK` 消失。
- 恢复前自动生成安全备份：`backup-20261103-041437-auto-*.zip`。
- 重新启动后书架和阅读器正常。

结论：通过。
