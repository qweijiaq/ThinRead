# 页边 ThinRead 功能盘点、问题审计与扩展建议

> 盘点对象：当前仓库 `reading-notes`，版本 `0.1.3`  
> 盘点日期：2026-11-05  
> 盘点范围：渲染层 `src/`、主进程 `electron/`、共享类型 `shared/`、现有文档与测试  
> 结论口径：以“代码里真实存在、用户能触发”的功能为准；文档写了但代码没有的，单独标为“文档漂移”

---

## 0.1 迭代记录

### 2026-11-05 · 第 1 步：阅读统计与偏好持久化

已完成：

- 阅读统计从“只存 localStorage、90 天截断”改为“localStorage 缓存 + 主进程 SQLite 持久化”，随数据库备份恢复；
- 取消 90 天删除，年度/同比和 7/30/100 天连续阅读里程碑恢复可信；
- 阅读计时增加活动门槛：连续 2 分钟无滚动/键盘/触摸/点击操作时暂停计时；
- 每日目标、自动续读写入 `settings.json`，随备份恢复；
- 修复 `monthSeconds` 只统计最近 14 天的问题；
- 新增数据库统计、备份恢复和 120 天连续阅读测试。

对应改动：`electron/db.ts`、`electron/settings.ts`、`electron/ipc.ts`、`electron/preload.ts`、`shared/types.ts`、`src/lib/reading-stats.ts`、`src/lib/preferences.ts`、`src/App.tsx`、`src/components/Reader.tsx`、`src/components/Library.tsx`，以及 `tests/reading-stats*.test.ts`、`tests/backup-blobs.test.ts`。

### 2026-11-05 · 第 4 步：笔记审计与覆盖度

按“读书笔记软件”的定位，跳过间隔重复/复习队列，先做与笔记质量直接相关的审计：

- 新增三个快捷筛选：待核对、无引用、人工修改；
- 审计摘要按当前书/类型/标签/关键词统计，不随快捷筛选缩小；
- 新增 `library:notes-audit` IPC 和数据库聚合查询；
- 新增 `tests/note-audit.test.ts`，并给 UI 回归增加审计摘要断言。

对应改动：`shared/types.ts`、`electron/db.ts`、`electron/ipc.ts`、`electron/preload.ts`、`src/components/NotesLibrary.tsx`、`src/lib/i18n.ts`、`src/styles.css`、`tests/note-audit.test.ts`、`tests/ui-smoke.js`。

### 2026-11-05 · 第 5 步：版本对比

对应改动：`shared/types.ts`、`electron/db.ts`、`electron/ipc.ts`、`electron/preload.ts`、`src/lib/text-diff.ts`、`src/components/VersionDiffDialog.tsx`、`src/components/ContentView.tsx`、`src/styles.css`、`src/lib/i18n.ts`、`tests/text-diff.test.ts`、`tests/content-versions.test.ts`、`tests/ui-smoke.js`。

### 2026-11-05 · 第 6 步：笔记导出 Markdown

- 笔记库新增「导出 Markdown」：把当前筛选结果写成独立 .md 文件夹；

- 生成 `index.md` 索引；文件名去重并做跨平台非法字符清理；
- 目标目录由用户选择，导出到 `ThinRead-notes-时间戳` 子目录，避免和已有文件混在一起；
- 可直接放入 Obsidian 仓库，或作为 Markdown 文件导入 Notion；
- 新增 `tests/note-export.test.ts`，UI 回归增加导出入口断言。

对应改动：`shared/types.ts`、`electron/db.ts`、`electron/ipc.ts`、`electron/preload.ts`、`electron/note-export.ts`、`src/components/NotesLibrary.tsx`、`src/lib/i18n.ts`、`tests/note-export.test.ts`、`tests/ui-smoke.js`。

## 0. 结论摘要

1. **产品不是单一阅读器，而是“导入 → 阅读 → 读薄 → 卡片 → 跨书关联 → 工作台 → 成书/分享”的一条完整链路。** 功能密度已经接近一个成熟的知识工作台，但入口和状态也偏多。
2. **当前没有账号、角色、管理员或云端权限体系。** 所有书、笔记、生成内容和设置都属于本机用户；“谁能用”主要由“有没有配置 Key / 有没有数据 / 是不是 macOS / 有没有联网”决定，而不是由身份决定。
3. **最大的产品资产是“本地数据 + 引用可核对 + 多种输出”。** 读薄稿、卡片、成书、分享卡、小红书、PDF/HTML 发布包构成了完整的“读完能产出”闭环。
4. **最大的风险不是功能少，而是“数据可信度”和“配置耦合”。** 阅读统计曾只保留 90 天却提供年度/同比（已在第 1 步修复）；Ollama、Readwise、TTS B 音色三处配置耦合（已在第 2 步修复）；TTS 的导出速度、费用确认仍待处理。
5. **建议顺序：先修数据与配置逻辑，再做阅读闭环，最后做同步/协作。** 不建议继续横向堆工具，先把“统计、备份、听读、证据审计”做扎实。
6. **产品定位是读书笔记软件，不做复习/记忆训练。** 后续功能优先围绕“笔记是否可信、是否覆盖全书、是否可复用/可导出”，不引入间隔重复、记忆卡复习或考试系统。

## 1. 先回答：什么身份的人才能使用？

### 1.1 当前没有“身份系统”

这是本地优先的 Electron 单用户应用：

- 没有登录、注册、管理员、成员、访客等角色；
- 没有服务端账号，也没有云端权限校验；
- 数据库、书籍文件、备份都在本机；
- API Key、Readwise Token、TTS Key 使用系统钥匙串加密；
- 书籍正文、笔记、生成内容在 SQLite 中明文保存；
- 任何能登录当前操作系统账户的人，都可以打开应用并看到全部内容；
- 应用可选开启本地密码锁；数据库仍明文，未做数据库级加密。

所以，**“身份”在本项目里不是权限身份，而是“配置状态 + 数据状态 + 系统环境”**。

### 1.2 五种实际可用状态

| 状态 | 判定方式 | 能用的范围 | 主要限制 |
| --- | --- | --- | --- |
| 首次用户 | 书架为空，且本机没有完成引导标记 | 引导、导入、演示生成、基础阅读 | 没有书时大量功能不可用 |
| 演示模式用户 | 设置里模型服务为“演示模式” | 导入、阅读、笔记演示生成、工作台演示报告、分享卡、导出 | AI 结果是固定样例；AI 排版禁用；TTS 仍需单独配置 |
| 真实模型用户 | 选择 DeepSeek / OpenAI / Anthropic / 智谱 / Kimi / 阿里云百炼 / OpenRouter，或本地 Ollama | 全部 AI 功能 | 需要 Key；Ollama 在“生成笔记”路径有额外问题，见 3.3 |
| 扩展配置用户 | 额外配置 Readwise Token、千问 TTS Key 或阿里云百炼 Key | Readwise 同步、听读、整章音频 | TTS 按字符计费 |
| 系统受限用户 | 非 macOS，或没有网络 | 本地导入、阅读、本地统计、本地搜索 | 扫描版 OCR 仅 macOS；网页导入、Readwise、AI、TTS 需要联网 |

### 1.3 功能门槛代码

| 门槛 | 含义 | 实现位置 |
| --- | --- | --- |
| 本地 | 不需要 Key、不需要联网 | 书架、阅读器、标记、书签、阅读位置、统计、本地搜索、备份 |
| 演示 | 演示模式返回固定样例 | 读薄、问答、费曼、工作台、成书、分享文案、小红书覆盖检查 |
| 真实模型 | 需要 API Key；Ollama 理论免 Key | `electron/ai/provider.ts`、`electron/ipc.ts` |
| Readwise | 需要 Readwise Token | `electron/readwise.ts`、设置页、导入弹窗 |
| 千问 TTS | 需要千问 TTS Key，或阿里云百炼主 Key | `electron/settings.ts`、`electron/tts.ts` |
| macOS | 扫描版 PDF OCR、扫描页理解 | `electron/import.ts`、`electron/ipc.ts` |
| 联网 | 网页导入、Readwise、AI、TTS、首次语义模型下载 | 对应 IPC 与 AI 服务 |
| 已有数据 | 需要书 / 章节 / 笔记 / PDF | 多数阅读与生成功能 |

### 1.4 如果以后要引入“身份”

当前架构适合“本机多档案”，不适合直接做团队权限：

- 本地多档案：每个档案独立数据库、设置和书架，用系统账户或应用锁隔离；
- 家庭共享：同一台机器多档案，或加密备份同步；
- 团队/多用户：需要把 SQLite 换成服务端数据库，并增加登录、租户、角色、审计日志和权限边界。

## 4. 新功能建议（发散）

## 8. 当前明确未做与原因

以下项目不是遗漏，而是需要先确定方案或涉及较大架构改动，当前版本暂不默认实现：

| 项目 | 原因 | 当前替代 |
| --- | --- | --- |
| 加密同步 / 跨设备 | 需要同步协议、冲突合并和端到端密钥设计，不能只加一个上传按钮 | 整库导出/导入 + 手动备份 |
| 数据库加密 | 需要迁移方案和系统钥匙串绑定；应用锁只是界面隐私层 | 可选应用锁；本地文件权限 |
| 敏感笔记单独隐藏 | 需要新的字段、搜索排除和导出排除规则 | 归档/回收站；应用锁 |
| 跨平台 OCR | 当前依赖 macOS Vision；Windows/Linux 需要新引擎和安装包 | macOS OCR；其他平台可导入文本/PDF |
| 完整英文界面 | 词典已覆盖外壳和大量新界面，但仍有 600+ 处中文字面量 | English Beta；持续迁移 |
| 按任务取消 | 当前工作台一次只跑一个 AI 任务，单控制器足够 | 取消当前任务 + 任务中心 |
| PDF 内搜索 | PDF 阅读器目前按页渲染，需要文本层和命中定位 | 章节搜索、全局搜索 |
| 更多分享模板 | 已有 6 种版式和纸/墨/苔绿三主题，继续增加维护成本较高 | 现有模板 + 自定义署名/品牌 |
